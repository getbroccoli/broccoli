# Thesaurus

The words Broccoli's code and docs use, and what each one means. Only Broccoli's own terms belong here; well-known ones such as job, model or mapping do not.

- **Instance**: one installation of Broccoli with its own database, for one company. The `instance` table holds its single row.
- **Mode**: how the instance is run, `self_hosted` or `managed`, set by `BROCCOLI_MODE`.
- **Owner**: the user who set up the instance. Identified by the user id, never by the email.
- **User**: a person who can sign in (Better Auth's `user` table).
- **Permission profile**: a named set of what a user may do, shown as "Permissions". Everyone has `EMPLOYEE`; a user may also have `ADMIN`, and the owner has `OWNER`. Not "role", which sounds like a job, nor "access level". See [permissions](permissions.md).
- **Built-in**: defined in Broccoli's code and changed by its releases; admins may extend it but not remove it, such as the built-in permission profiles. Its opposite is **custom**. Not "system", which means Broccoli acting on its own.
- **Owner sign-in method**: how the managed owner proves who they are at the accounts service, Google or email; learned from the sign-in ticket. The sign-in page offers only that method.
- **Account**: one way a user signs in, such as a password (`credential`) or managed sign-in (Better Auth's `account` table). A user can have several.
- **Session**: a signed-in browser, carried in a cookie and stored in the `session` table.
- **Setup**: the first-run flow of a new instance, step by step: the company name, then the import of its people, then on self-hosted instances the owner account, created last by the setup holder through `POST /api/auth/setup`. A managed owner signs in before setup and ends it on the ready step.
- **Setup step**: where a new instance is in setup: `company`, `import`, `owner` (self-hosted only), `ready` (managed only: the owner sees what setup added before using Broccoli), `done`. Not to be confused with employee onboarding, an HR process. The web app's step list shows one more, the setup review step, inside `import`.
- **Setup session**: on a self-hosted instance before the owner exists, the server-side record that one browser holds setup: the hash of a token in the `broccoli_setup` cookie, valid three days after the holder last opened setup. Setup stays locked to it, even after it expires, until the database is dropped.
- **Provisional owner**: the owner a self-hosted demo starts with: a user without credentials, signed in in the browser that held setup, until they exit the demo or it ends seven days later.
- **Setup holder**: the browser holding the setup session, and the security context it acts as. It may do the setup steps and nothing else.
- **External agent**: a coding agent operating outside Broccoli, such as Claude Code or Codex, acting through its API on the setup holder's or owner's behalf during setup only. "External" means outside the application, not necessarily on another machine. A person's own agent connected over MCP is a connected agent.
- **External agent one-time code**: the secret in the prompt "Add your files" shows for the owner's external agent; valid once, for two hours.
- **External agent session**: what the external agent gets for an external agent one-time code: a secret token and the security context it acts as. It lasts two hours at most, works only while setup is at the import step with the external agent chosen, and ends on Disconnect or a new code.
- **Connected agent**: a person's own AI client, such as Claude, ChatGPT, Claude Code or Codex, connected to Broccoli over MCP and acting as that person, with their permissions; one per person, shown as "Your agent".
- **Agent connection**: a person's grant to their connected agent, from Allow until they disconnect it on Your agent, connect another agent, reset their password, or leave it unused for 30 days.
- **Agent invitation**: the card on Today that invites a person to connect their own agent. Each person closes it for good, on every browser; it never shows while their agent is connected.
- **Setup review step**: the setup page after the import step, "Review your people", where the owner sees every import employee, settles what its records disagree on, fixes values, leaves some out, and approves. Only the web app knows it: the instance stays at the `import` setup step until setup approve.
- **Data folder**: `DATA_DIR`, the folder for files that must survive restarts, such as `secrets/`.
- **File**: bytes with a MIME type that a module stores in the `files` table, such as the company logo. The module that references it decides who may see it.
- **Primitive**: one of the four building blocks every HR feature is made of: records, tasks, calendar and processes.
- **Record**: a module's main entity, such as an employee or the company.
- **Today**: the home page, where a person lands after setup and after signing in. It shows what needs them today; for now only the agent invitation.
- **Task**: work asked of one person, its assignee, by its asker or a process step. To do, Waiting, Done or Cancelled; only its assignee and its asker see it.
- **Assignee**: the person who does a task. Not "holder", which is the setup holder. Code: `assignee_employee_id`.
- **Asker**: the person who asked for a task; none on a process step's task. Code: `asked_by_employee_id`.
- **Subject**: the employee a record is about, which permission scopes are measured against (see [permissions](permissions.md)). A task's subject is shown and gives them no access. Code: `subject_employee_id`.
- **Record** (of a task or process run): the record it acts on, of any type, such as a time off request. Code: `record_type`, `record_id`. **My tasks** is the Tasks page: Needs you, Waiting on others and Resolved recently.
- **History**: every change to a record, kept as history lines in the `record_history` table and shown on the record. The product word; "audit" stays internal and means a separate security trail.
- **History line**: one change to one record: its change author, when, its change cause, its change reason and each changed field's old and new value. Appended in the transaction of the change; only a purge, such as Exit demo or Reset setup, deletes lines.
- **Change author**: who made a change to a record, from the security context: a signed-in user, Broccoli itself, the setup holder or the external agent.
- **Change cause**: why a change to a record happened or what started it, such as `EDITED_DIRECTLY` or `ADDED_FROM_IMPORT`, with the id of what caused it when there is one. The module whose action is the cause declares it.
- **Change reason**: why, in the change author's own words: `changeReason` on an input, the reason on its history line.
- **Employee**: someone who works for the company; later also agents and robots. The People area lists employees.
- **Employment**: a person's work for the company over a period, with its start and end dates and their direct manager; one at a time, never overlapping. A person's start date is the start of their first employment. Not "contract", which in the UK means the written contract of employment.
- **Location**: a named place where people work, such as an office or "Remote", which admins manage in Settings; a person is in one at a time. Not "site" or "office", which a staff file may call it.
- **Terms**: a named set of people who share the same working pattern and time off policies, such as "England and Wales"; the terms are assigned a working pattern version and one policy version per time off type, from dates. A person is on one set of terms at a time. Always plural, like the terms of a contract. Code: `terms`.
- **Default terms**: the seeded terms, key `default_terms`, which a new person starts on unless their location has its own; named "England and Wales" until turning time off on gives them the nation the owner picked for a staff file without locations; a location's default terms are the terms a person added at that location starts on, which admins choose in Settings › Locations; null means the default terms. Changing a location's terms never moves anyone already there, and changing a person's location never changes their terms. Code: `default_terms`, `locations.default_terms_id`.
- **Standard working week**: one of the UK weeks an owner picks for terms when turning time off on: Monday to Friday at 7.5 (the seeded week), 8 or 7 hours a day, or Monday to Thursday at 8 hours. Code: `StandardWorkingWeek`.
- **Time off is on**: any terms have a time off policy assigned; there is no stored flag. While time off is off, nobody has an allowance and nobody can book time off.
- **Company defaults** (setup page): the setup page after the review where the owner picks the company defaults (one Annual leave policy and one standard working week for everyone) and whose bank holidays apply (one nation for everyone, or each location's), then turns time off on or skips it; turning it on happens as setup finishes.
- **Working pattern**: a way of working: the minutes worked on each weekday, Monday to Sunday, in its versions. Terms and people are assigned its versions; a pattern made on the terms screen has no name. Not "workload", "schedule" or "policy".
- **Version**: a working pattern's or time off policy's settings, with no dates; a draft until published, never edited once published. Not "period". Code: `working_pattern_versions`, `time_off_policy_versions`.
- **Draft**: a version saved and not published yet, such as a working week edited on a set of terms; it changes nobody's settings. The terms screen marks terms with drafts, and the version's `revision` counts its saves. Not "pending change". Code: `status = 'draft'`.
- **Published**: a version that can be assigned and never changes. **Publish** on a set of terms publishes all of their drafts and assigns them, from one date, to the terms and to every other owner using what they replace that the admin keeps ticked.
- **Assignment**: a version given to one employee or one set of terms from a start date to an inclusive end date, or open-ended; an owner's assignments never overlap, and for a person their own wins over their terms'. Code: `working_pattern_assignments`, `time_off_policy_assignments`.
- **Bank holiday calendar**: one nation's bank holidays (England and Wales, Scotland or Northern Ireland), chosen on a working pattern version.
- **Standard leave policy**: one of the three Annual leave policies Broccoli ships as code constants, which turning time off on copies into terms and code finds by key: the UK statutory minimum (28 days for a five-day week, at most 28, bank holidays included), 20 days plus bank holidays, and 25 days plus bank holidays; each leave year starts on 1 January.
- **Time off**: everything a person is away from work for, of any time off type (Annual leave, Sickness, Family leave, Other or the company's own). Not "PTO", "vacation", "holiday" or "absence".
- **Booking**: time off an admin records for a person, approved straight away; cancelling it gives its days back. Not "request", which waits for approval, nor "absence".
- **Who's out**: the Time off page's month of everyone's time off, bank holidays and days off. A private type shows to colleagues as **Off**.
- **Allowance figures**: what a person's panel shows for a time off type with an allowance, in days for one leave year: **entitlement** (everything granted, bank holidays on top and adjustments included), **bank holidays** (those the year takes from it), **used** and **remaining** (entitlement less bank holidays and used).
- **Days recorded**: the days of a time off type with no balance, such as Sickness, a person has in a calendar year; a half day counts 0.5.
- **Security context**: who is calling application code: a signed-in user, and whether they are the owner; the setup holder; or the system.
- **System**: Broccoli acting on its own, such as creating the owner at setup or seeding the demo company after it.
- **Company**: the business the instance belongs to; its name and logo. One per instance.
- **Brand lookup**: finding a company's logo from the owner's email domain, through the favicon service at `BRAND_LOOKUP_URL`.
- **Domain event**: something that happened in the domain, published by one module in a transaction and handled by others after the commit, such as `instance.owner_claimed`.
- **Demo data**: the sample company a new instance starts with. Exit demo deletes it with everyone added while it is present, and their history, and setup starts again.
- **Import**: every import source and its records, waiting for review before they become records of their module. One per instance.
- **Import source**: one place people come from, such as the connected Slack workspace or an uploaded file. It owns its import records.
- **File source**: a staff file the owner uploaded as an import source. Its records come from the file's rows once the file is mapped: by Broccoli's model, or by the external agent's answers to Broccoli's masked questions (_answered mapping_); after an _original file read_, from the people AI read in the whole file.
- **Original file read**: the owner's consent, per file source, that AI may read that file in full, personal data included: Broccoli's model through the chosen AI source, or the external agent. Its people then replace the file's records. A PDF, whose rows Broccoli cannot mask, waits for it; consent lasts until setup completes.
- **Import record**: one record as one source proposes it, such as one row of a staff file, with the source's values as they came; not yet a record of its module.
- **Import employee**: the employee an import will create: the import records that share a work email, or one without an email. Each value is the owner's pick or typed value, else the first source's: files oldest first, then Slack.
- **Ready import employee**: an import employee complete enough to become an employee under the employee rules, with an email no employee has yet. The others are incomplete import employees, or have a taken email.
- **Setup approve**: the setup review step's "Add N people" button, which completes the import step, once. The ready import employees that are not left out become employees, with the values and photos review shows, when setup completes; the others are not added. Until then, "Back" on setup's last step reopens the review. The import is deleted when setup completes.
- **Reset setup**: the workspace menu action that starts a finished setup over: every employee and their history is deleted and setup goes back to the `company` step; the company and the AI choice stay. The demo's provisional owner exits the demo instead.
- **Invite**: an admin's offer to one person to sign in, by a single-use invite link valid seven days, with the permission profiles the person gets. One open invite per person; inviting again replaces it.
- **Invite link**: `<origin>/invite#<token>`; only the token's hash is stored, so a link is shown or emailed once and never again.
- **Invite delivery**: how an invite reaches the person: `SENT_BY_EMAIL` while the instance sends email (a self-hosted mail choice, or the mail relay on managed), else `COPIED_BY_OWNER`, a link the admin copies and sends themselves.
- **Sign-in state**: whether a person can sign in: not invited, pending (an invite is open or has expired), or joined.
- **Joined**: a person whose user is linked to their employee record (`employees.user_id`), after accepting an invite; the owner joins when setup finishes, as the person they chose on "Who uses Broccoli".
- **Setup invite audience**: who the owner invites as setup finishes, chosen on the "Who uses Broccoli" page after setup approve: only admins (nobody), admins and managers (the people who manage someone), or everyone. A one-time choice, never stored: later invites go through People.
- **Mail choice**: how a self-hosted instance sends email: the owner's SMTP server, their Resend key, or no email. Saved on the instance in Settings; password reset works only while email is chosen.
- **Mail relay**: Broccoli's sender for managed instances, at `MANAGED_MAIL_RELAY_URL`. The instance sends each email as blocks with its instance credential; the relay renders it in Broccoli's layout and sends it as "<sender> via Broccoli" and refuses links outside the instance's own origin. Self-hosted instances never use it.
- **Slack connection**: the instance's connected Slack workspace and its encrypted token, owned by the `slack` module. Connecting imports nothing; the import reads the workspace when the owner asks.
